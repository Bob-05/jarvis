# 🤖 J.A.R.V.I.S.

**Just A Rather Very Intelligent System** — локальный голосовой ИИ-ассистент для Windows 11.

Работает полностью автономно: распознавание речи, генерация ответов, синтез голоса, выполнение
команд Windows и поиск в интернете — всё локально, без облачных ключей.

---

> ⚠️ **Внимание: проект находится в стадии активной разработки (alpha).**
> Он работает и развивается, но возможны ошибки, незавершённые функции и изменения
> поведения без предупреждения. Используйте с осторожностью и делайте резервные копии
> своих данных. Полный список ограничений — в разделе
> [«Известные проблемы и ограничения»](#известные-проблемы-и-ограничения).

## ✨ Возможности

- 🎤 **Голосовой интерфейс** — запись с микрофона с VAD (автопределение начала/конца речи)
- 🧠 **Локальный LLM** через [LM Studio](https://lmstudio.ai) — сам запускает и останавливает сервер
- 🗣️ **STT — распознавание речи**: *Vosk* (лёгкая офлайн-модель) или *Kairos ASR / GigaAM*
- 🔊 **TTS — синтез речи**: *Silero TTS v5* (русский голос «eugene») или *Piper*
- 💬 **Память** — история диалогов + **семантический поиск** по эмбеддингам
- 🌐 **Интернет** — поиск через SearXNG (Docker) с фолбэком на DuckDuckGo, чтение страниц
- ⚙️ **Команды Windows** — с проверками безопасности и подтверждением опасных операций
- 🖥️ **Два интерфейса**: Desktop (pywebview + трей + визуализация «орба») и Console (Rich-меню)
- 🔋 **Экономия ресурсов** — ограничение GPU/контекста/приоритета LLM, автоостановка при простое

## 🧱 Архитектура

```
jarvis/
├── audio/      # запись с микрофона, VAD, ресемплинг
├── core/       # JarvisCore (бизнес-логика, событийная шина)
├── llm/        # менеджер LM Studio (чат, эмбеддинги, life-cycle сервера)
├── memory/     # история диалогов, векторное хранилище, семантический поиск
├── stt/        # распознавание речи: Vosk / Kairos ASR
├── tts/        # синтез речи: Silero / Piper
├── tools/      # команды Windows, поиск, чтение страниц, SearXNG
├── ui/         # Rich-консоль, интерактивные меню, логгер
└── web/        # FastAPI + WebSocket, статика, pywebview-десктоп, трей
```

Ядро общается с UI-слоями через очередь событий — консоль и веб-панель подписываются
на одни и те же события.

## 🖥️ Требования

| Компонент | Назначение |
|---|---|
| Windows 10/11 | меню используют `msvcrt`, команды — cmd/PowerShell |
| Python 3.10+ | синтаксис кода |
| [LM Studio](https://lmstudio.ai) с локальной LLM-моделью | генерация ответов |
| Микрофон | голосовой ввод |
| Docker Desktop *(опционально)* | SearXNG |
| Модель Vosk *(опционально)* | лёгкий STT |

## 🚀 Быстрый старт

```powershell
# 1. Клонируйте репозиторий
git clone <url-репозитория>
cd jarvis_project

# 2. Виртуальное окружение и зависимости
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 3. Локальные файлы настройки из шаблонов
Copy-Item config.example.json config.json
Copy-Item system_prompt.example.txt system_prompt.txt

# 4. (Желательно) модель Vosk для русского языка:
#    https://alphacephei.com/vosk/models  → распакуйте в папку проекта

# 5. Запуск (по умолчанию — Desktop UI)
python -m jarvis

# Консольный режим с интерактивными меню
python -m jarvis --console
```

> Для голоса Silero нужна библиотека `pip install silero` (тянет torch/torchaudio).
> Альтернатива — `pip install piper-tts` + ONNX-модель.

## ⚙️ Настройка

### `config.json`
Создаётся из `config.example.json`. Ключевые параметры:

| Ключ | Описание |
|---|---|
| `wake_word` / `require_wake_word` | активационное слово и режим |
| `lm_studio_url`, `lm_studio_auto_start/stop` | управление сервером LM Studio |
| `llm_*` | ограничения ресурсов LLM (GPU, контекст, приоритет) |
| `stt_engine` | `"vosk"` или `"kairos-asr"` |
| `tts_engine` / `silero_speaker` | `"silero"` или `"piper"`, голос |
| `search_engine_priority` | `"searxng-first"`, `"ddg-first"`, `"ddg-only"` |
| `semantic_search_enabled` / `semantic_top_k` | семантическая память |

### `system_prompt.txt`
Персональный системный промпт (копируется из `system_prompt.example.txt`). Задаёт характер,
формат ответов и правила работы с инструментами. Редактируется в панели ⚙ Settings
(Desktop-версия), изменения применяются без перезапуска.

### Поиск через SearXNG (Docker)

Рядом лежит [`searxng/docker-compose.yml`](searxng/docker-compose.yml). Jarvis сам поднимает
контейнер через Docker Desktop и останавливает его при выходе.
Если Docker не установлен — просто выберите
`Только DuckDuckGo` в меню поиска.

## 📦 Сборка единого .exe

### Простой способ

Сборка выполняется на Windows. Перед сборкой установите зависимости проекта и PyInstaller:

```powershell
pip install -r requirements.txt
pip install pyinstaller
python build_exe.py
```

Результат: `dist/Jarvis.exe` — однофайловый исполняемый файл, который можно перенести на
другой компьютер с Windows (устанавливать Python там не нужно). Скрипт `build_exe.py`
собирает проект в режиме `--onefile --windowed`.

### Что входит в .exe

- весь код и веб-интерфейс (`jarvis/web/static`);
- интерпретатор Python и все используемые библиотеки;
- шаблоны `config.json` и `system_prompt.txt` — при первом запуске они распаковываются
  рядом с `.exe` и дальше правятся как обычные файлы (см. «Файлы проекта»).

### Что не входит

- **Модели Vosk** — папку скачанной модели (`vosk-model-*`) нужно положить рядом с `.exe`
  и указать в настройках;
- **голоса Silero / Piper и Kairos ASR** — эти движки требуют PyTorch и по умолчанию в exe
  не добавляются. Чтобы включить их, установите соответствующие библиотеки в окружение
  сборки и при необходимости раскомментируйте блок `--collect-all torch / torchaudio`
  в `build_exe.py` — размер exe при этом вырастет на сотни мегабайт;
- **LM Studio и Docker Desktop** запускаются приложением отдельно и в exe не встраиваются.

### Особенности

- однофайловый exe при запуске распаковывает себя во временную папку — первый старт
  медленнее последующих;
- каталоги `build/` (промежуточные файлы) и `dist/` (готовый результат) появляются после сборки;
- некоторые антивирусы могут ложно помечать файлы PyInstaller — это известная особенность
  упаковки `onefile`, а не вредоносный код.

## 🔐 Безопасность команд

Jarvis исполняет команды Windows с несколькими уровнями защиты:

- чёрный список опасных паттернов (`del`, `format`, `shutdown`, `reg ...`, `taskkill` и т.д.);
- запрет подстановки `& | ; > <` в командах;
- подтверждение пользователя (в консоли или в Web UI) перед опасной командой;
- контент из интернета (поиск, веб-страницы) никогда не выполняется — это данные, а не инструкции.

## 🗂️ Файлы проекта

Проект работает с обычными файлами рядом с приложением. В составе проекта идут **шаблоны**,
из которых создаются рабочие файлы. **Имена рабочих файлов закреплены в коде**
(`jarvis/constants.py`) — их нужно соблюдать, иначе приложение их не найдёт.

| Шаблон | Рабочий файл | Назначение |
|---|---|---|
| `config.example.json` | `config.json` | настройки |
| `system_prompt.example.txt` | `system_prompt.txt` | системный промпт |

При запуске из исходников рабочие файлы нужно создать один раз:

```powershell
Copy-Item config.example.json config.json
Copy-Item system_prompt.example.txt system_prompt.txt
```

Остальные файлы приложение создаёт само, а их имена можно поменять в `config.json`:

| Файл | Назначение | Ключ настройки |
|---|---|---|
| `dialog_history.json` | история диалогов | `history_file` |
| `history_embeddings.json` | векторы семантического поиска | `embeddings_file` |
| `jarvis_log.txt` | лог (в подробном режиме логирования) | `log_file` |

В собранном `.exe` рабочие файлы `config.json` и `system_prompt.txt` создаются автоматически
из встроенных шаблонов при первом запуске.

## Известные проблемы и ограничения

> ⚠️ Этот раздел фиксирует текущее состояние проекта и **не является списком исправлений**.
> Проблемы перечислены для прозрачности и будут закрываться по мере развития. Часть из них
> сознательные компромиссы ранней разработки.

### 🧩 Функциональные

- **История диалогов без ротации** — `dialog_history.json` растёт неограниченно; каждая новая
  запись перезаписывает весь файл целиком, на длинных сессиях это замедляется.
- **Нет тайм-аута у запросов к LLM** — при зависшем/перегруженном LM Studio интерфейс может
  «застрять» в состоянии **ДУМАЮ** без возможности отмены.
- **Нет стоп-команды** — нельзя прервать текущий запрос или озвучку из UI/консоли.
- **Всё в памяти** — история диалогов и эмбеддинги загружаются в оперативную память целиком;
  при большом объёме накопленной истории растёт потребление RAM.
- **Жёсткий выход при недоступном движке** — если в `config.json` выбран STT/TTS, который
  не установлен (`kairos-asr`, `silero`, `piper-tts`), приложение завершается с ошибкой
  вместо аккуратного предупреждения.
- **Kairos ASR требует ffmpeg** — наличие `ffmpeg` в PATH заранее не проверяется, ошибка
  появляется только при инициализации.
- **Запуск из исходников требует локальных файлов** — `python -m jarvis` без `config.json`
  работает на настройках по умолчанию, но без `system_prompt.txt` завершается (в `.exe`
  шаблоны распаковываются автоматически при первом запуске).
- **Семантическая память зависит от эмбеддинг-модели** — если в LM Studio нет подходящей
  модели эмбеддингов или она недоступна, семантический поиск молча отключается.
- **Настройки только в desktop-режиме** — панель настроек, системный промпт и смена моделей
  работают только через pywebview (недоступно, если открыть веб-интерфейс обычным браузером).
- **Зависимость от CDN** — веб-статика грузит three.js / marked / DOMPurify из интернета:
  без сети орб и markdown-разметка не работают.
- **В .exe не входят «тяжёлые» движки** — сборка через `build_exe.py` по умолчанию не
  включает Kairos/Silero/Piper; готовый exe рассчитан на Vosk + базовые функции.

### 🔐 Безопасность

- **WebSocket без аутентификации и проверки Origin** — сервер на `127.0.0.1:8765` принимает
  сообщения от любого локального клиента: любой процесс или страница браузера может отправлять
  запросы и **подтверждать опасные команды**.
- **Фильтрация команд по ключевым словам** — чёрный список (`del`, `format`, `taskkill` и т.д.)
  строится на подстроках и обходится приёмами cmd (переменные окружения, альтернативные имена
  утилит, нестандартные пути), поэтому не является строгой границей безопасности.
- **Логи могут содержать чувствительные данные** — в подробном режиме весь текст диалогов и
  команды пишутся в `jarvis_log.txt` открытым текстом.
- **Не для внешних сетей** — сервер слушает loopback; публикация наружу без аутентификации
  запрещена текущей реализацией.

### 🛠️ Качество и разработка

- **Нет тестов** — ни модульных, ни интеграционных; регрессии возможны незаметно.
- **Нет CI / линтеров / type-checking** — код не проверяется автоматически.
- **Зависимости не закреплены** — версии в `requirements.txt` заданы как минимальные (`>=`),
  без lock-файла; обновления пакетов могут ломать совместимость.
- **Дублирование логики** — `main.py` и `jarvis_exe.py` содержат почти одинаковые процедуры
  запуска; правки необходимо вносить в оба файла синхронно.
- **Крупные монолитные модули** — `jarvis_core.py` и `lm_studio.py` превышают 800 строк,
  сложны для сопровождения.
- **Хрупкая интеграция с pywebview** — `JsApi` сознательно использует приватные атрибуты
  (`_config`, `_core`) для обхода интроспекции; обновление pywebview может сломать эту схему.
- **Нет интернационализации** — тексты интерфейса и сообщения зашиты в коде на русском.
